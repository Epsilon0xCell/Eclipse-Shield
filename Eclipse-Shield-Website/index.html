01What this is

Eclipse Shield is my focus tool. I built it because simple blocklists do not understand context. A site that is a distraction during one kind of work is the work itself during another.

So I set my current context and goals first. Eclipse Shield checks sites against my explicit allow and block lists, my category rules, and that context. When a site matches no rule and I have given it a Gemini key, it asks the AI. When I have not, it stays with the rules and says so.

The backend is a Python Flask service, and a browser extension for Chrome and Opera talks to it. It is a personal tool built to solve my own problem, and I keep its claims at exactly what the code does.

02How it decides

SituationWhat happens
Site is on my allow listIt loads. My explicit word beats every rule under it.
Site is on my block listIt is blocked, in real time, without a page refresh.
A category rule matchesThe rule for that category applies to the current context.
No rule matches, Gemini key setThe AI reads my stated context and goals and decides, and asks me questions to keep the context honest.
No rule matches, no keyNo pretending. The rules decide, and /health reports "ai": "local-only" to anyone who asks.

03The extension, as it actually looks

  • Context first: I define my work domains and productivity goals, and blocking follows that context.
  • Adaptive questions: the tool asks about my current task so its picture of my context does not go stale.
  • Input validation, rate limiting, and API key handling with CSRF protection are in the backend; SECURITY.md in the repo carries the detail, and I will not summarise it into claims it does not make.

04Run it

Without Docker, on any platformpython3 -m venv venv && source venv/bin/activate pip install -r requirements.txt -r requirements-secure.txt python3 secure_app.py # serves http://localhost:5000 curl http://localhost:5000/health
The automated test suitepython3 -m pytest tests/ -q

On macOS there is also an installer path: ./install-local.sh, with the QUICKSTART.md guide in the repo. A Gemini key is optional, set in api_key.txt or as the GOOGLE_API_KEY environment variable. Requirements beyond that, including Redis, Nginx, and Docker for a production shape, are listed in docs/REQUIREMENTS.md in the repo.

05Where it stands, honestly

Without a Gemini key this does not pretend to be AI powered. It runs in local rules-only mode and the /health endpoint says so in plain JSON: "ai": "local-only". I consider that honesty a feature, and it is the standard I hold the rest of my project pages to as well.

This repo also carries a real docs/ folder with installation, deployment, API, and architecture documents. I left every one of them where they were. This site lives in Eclipse-Shield-Website/ and the tool's own documentation was not moved or rewritten to make room for it.
